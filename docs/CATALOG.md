# Наполнение каталога

1. Откройте `docs/media-catalog.html` или `/media-library`. Все 40 исходников имеют ID `MEDIA-01` ... `MEDIA-40`; соответствие исходным именам и контрольные суммы записаны в `src/data/media.json`.
2. Подтвердите с владелицей форму, права на фотографию, состав, размеры, технологию и реально совместимые опции. Одно изображение не доказывает материал, тип фитиля или аромат.
3. Добавьте объект `Product` в `src/data/products.ts`. Текущий массив `references` является компактной загрузкой демонстрационных форм; подтверждённые товары можно записывать полными объектами вместо этой фабрики или добавлять к массиву.
4. Используйте уникальные стабильные `id` и `slug`. Смена ID делает старую конфигурацию корзины недействительной. `published: false` скрывает изделие и блокирует его серверную проверку.
5. Укажите `name`, `short`, `description`, `category`, `image` и `photos`. Не переносите чужое имя, подпись, логотип или историю из фотографий.
6. Заполните только проверенные `candleTypes`, `technology` и `decorKinds`. Пустой массив и `null` означают отсутствие подтверждённых сведений; соответствующий фильтр не выдаёт такой товар.
7. В `sizes` и `materials` оставьте только доступные варианты. Текущая модель требует хотя бы один размер и материал. Если материал не предлагается на выбор, укажите единственный проверенный вариант. Для нового материала/размера согласованно обновите конфигурацию тарифов, Zod enum и тесты.
8. `aromas` содержит объекты `{ id, label }` только для подтверждённых ароматов. «Без аромата» доступно отдельно. Пустой массив не предлагает вымышленные запахи. `allowDecor: false` убирает допдекор и запрещает его на сервере.
9. `basePrice` хранится в целых рублях; текущая база 1500. Доплаты редактируются в `src/lib/config.ts`: размер 0/500/1000, материал 0/100/200 (предварительно), аромат 200, декор 300. При подтверждении отдельно проверьте тарификацию материалов.
10. После приёмки установите `approved: true`, `optionsStatus: 'confirmed'`. Одного общего `CATALOG_APPROVED=true` недостаточно: сервер проверяет каждый товар.

Пример добавления подтверждённого товара (значения ниже являются структурным примером, не данными ассортимента):

```ts
const confirmedProduct: Product = {
  id: "stable-owner-approved-id",
  slug: "owner-approved-slug",
  name: "Подтверждённое название",
  short: "Проверенное краткое описание",
  description: "Описание, согласованное с владелицей",
  image: "/media/approved-photo.webp",
  photos: ["/media/approved-photo.webp"],
  category: "Скульптурные",
  candleTypes: [],
  technology: null,
  decorKinds: [],
  sizes: ["small"],
  materials: ["palm"],
  aromas: [],
  allowDecor: false,
  basePrice: 1500,
  published: true,
  approved: true,
  optionsStatus: "confirmed",
};
```

Не копируйте пример в коммерческий каталог без проверки всех полей. Технические ограничения: до 20 конфигураций в заявке, до 20 единиц на конфигурацию. Это ограничения защиты сервера, не маркетинговые условия продажи.

Для новых исходников сохраните оригинал в `фото`, затем выполните `npm run media`. Генератор рассчитывает ID по номеру `photo_N_...`: при расширении сохраняйте уникальные последовательные номера и не меняйте имена существующих исходников. После генерации проверьте соответствие ID и визуально просмотрите фотографии. Генератор пересоздаёт производные файлы и манифест, оригиналы не записывает.

При необходимости нескольких изображений добавьте пути в `photos` и расширьте галерею страницы товара: сейчас интерфейс показывает основную фотографию, а поле подготовлено для дальнейшей галереи.

Название и описание бренда находятся в `src/lib/config.ts`, знак сайта в `public/icon.svg`. Текущий логотип набран текстом и не зависит от стороннего графического файла.
