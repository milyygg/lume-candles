# Telegram и развёртывание

## Переменные окружения

| Переменная                     | Назначение                                                                                                      |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `ORDER_MODE`                   | `test` по умолчанию; `real` включает строгую проверку конфигурации                                              |
| `NEXT_PUBLIC_SITE_URL`         | Точный публичный origin, например `https://your-domain.ru`; задаётся до сборки                                  |
| `DATABASE_URL`                 | PostgreSQL, обязательно для real; используйте TLS с проверкой сертификата согласно провайдеру                   |
| `SQLITE_PATH`                  | Только локальные тесты, по умолчанию `./data/lume.sqlite`                                                       |
| `TELEGRAM_BOT_TOKEN`           | Секрет бота, только сервер                                                                                      |
| `TELEGRAM_CHAT_ID`             | Подтверждённый ID личного чата/группы, доступного боту                                                          |
| `ORDER_SIGNING_SECRET`         | Случайный секрет не короче 32 символов, одинаковый на всех инстансах                                            |
| `CRON_SECRET`                  | Отдельный случайный секрет от 32 символов для endpoint повторов                                                 |
| `IP_HASH_SECRET`               | Отдельный случайный секрет от 32 символов для хеширования IP                                                    |
| `TRUST_PROXY`                  | `true` только за доверенным прокси, который перезаписывает заголовок IP                                         |
| `CATALOG_APPROVED`             | `true` после проверки каталога, тарифов и прав; нужны также флаги каждого товара                                |
| `LEGAL_APPROVED`               | `true` только после замены и проверки юридических черновиков                                                    |
| `NEXT_PUBLIC_TELEGRAM_CONTACT` | Подтверждённая ссылка `https://t.me/username`; не секрет                                                        |
| `NEXT_PUBLIC_TELEGRAM_INVITE`  | Зарезервированное значение приглашения; текущая страница явно показывает предоставленную ссылку как приглашение |

Все `NEXT_PUBLIC_*` значения публичны и встраиваются при сборке. Не кладите туда токены или секреты. `.env.local`, база, дампы и `data/` исключены из Git. Секреты передаются через менеджер окружения хостинга. Пример не содержит настоящих значений.

## Настройка Telegram

1. Владелица создаёт бота через официальный BotFather и передаёт токен безопасным способом для серверного окружения. Токен не вводится в браузерный код или коммиты.
2. Владелица открывает бота и отправляет `/start`, либо добавляет его в согласованную группу с правом отправлять сообщения.
3. Разработчик получает и проверяет `chat_id` через Bot API в защищённой среде. Не публикуйте ответы `getUpdates`: они могут содержать контакты и сообщения. Предоставленная `https://t.me/+qQX5YNnktWlkOTIy` является приглашением и не заменяет `chat_id` или личный username.
4. Задайте PostgreSQL и остальные секреты. Подтвердите каталог, материалы и документы. До этого реальный endpoint возвращает 503, а неподтверждённые товары сервер не принимает.
5. Настройте планировщик POST-запросов на `/api/internal/retry` раз в минуту с `Authorization: Bearer <CRON_SECRET>`. Секрет хранится у планировщика; не помещайте его в URL. На один вызов обрабатывается до 10 записей последовательно. При большом потоке выделите worker.
6. В тестовой инфраструктуре проверьте создание заявки, получение в конкретном чате, отсутствие повторного заказа при повторной отправке и восстановление после временного отказа Telegram.
7. Только после реального испытания переключите `ORDER_MODE=real` и пересоберите сайт. В текущем проекте настоящий бот и PostgreSQL не проверялись.

Формат уведомления содержит номер, все конфигурации, количество, цену каждой единицы, предварительный итог, имя и добровольный контакт. Очень длинный состав делится на несколько сообщений с одним номером заказа. HTML/Markdown parse mode не включается, поэтому введённый текст не интерпретируется как разметка. Потеря ответа Telegram может привести к повторному уведомлению с тем же номером. Заявка в базе одна.

Возможность общения с покупателем через бота оставлена для отдельной интеграции: уникальный ID уже есть, но deep link, customer chat ID, webhook и автоматическая переписка пока не реализованы и не обещаются.

## Production на Node.js

1. Подготовьте Node.js 24+, HTTPS-домен, закрытую PostgreSQL, резервные копии и менеджер секретов. Локальная SQLite не предназначена для real/serverless/нескольких инстансов.
2. Перенесите исходники, `public`, конфигурацию и lockfile. `node_modules`, `.next`, локальные заявки и оригиналы с неподтверждёнными правами не публикуйте автоматически. Для production оставьте только разрешённые медиа и закройте/уберите страницу исходников, если она не нужна публике.
3. Выполните `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` с целевыми переменными окружения.
4. Запустите `npm start` под менеджером процессов. По умолчанию приложение слушает `127.0.0.1:3014`, reverse proxy направляет туда запросы. В контейнере при необходимости смените bind на `0.0.0.0`.
5. Настройте HTTPS, ограничение размера/времени входящих запросов, rate limiting и корректный IP-заголовок. API дополнительно ограничивает тело до 16 КБ и число заявок до 5 за 10 минут на доверенный хешированный IP. Без доверенного прокси лимит общий.
6. Проверьте, что `NEXT_PUBLIC_SITE_URL` совпадает с origin формы. Блокировки по Origin не являются самостоятельной антибот-защитой.
7. Настройте POST-планировщик и мониторинг pending-заявок. Очередь не теряется после перезапуска, но без планировщика повторные попытки не выполняются автоматически.
8. Закройте доступ к PostgreSQL из публичной сети, ограничьте пользователя базы, настройте TLS, резервирование и регулярное удаление персональных данных по согласованному сроку. SQLite-файлы и бэкапы локальных тестов также не должны попадать в публичный каталог.

Приложение создаёт таблицы `orders`, `rate_limits` при первом запросе. В `orders` поле `notification` имеет состояния `test`, `pending`, `sent`; это состояние уведомления, а не стадия производства. Рабочий процесс изготовления и отдельная панель управления в этот этап не входят.

Официальные контракты: [Telegram Bot API](https://core.telegram.org/bots/api), [Next.js deployment](https://nextjs.org/docs/app/getting-started/deploying).
